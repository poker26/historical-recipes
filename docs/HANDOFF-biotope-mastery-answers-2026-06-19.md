## 1. Q3 — авто-роутинг по царству (тумблер УБРАН)
`POST /api/identify` теперь дефолт **`kingdom=auto`** (как ты и шлёшь). На `auto`:
- сначала бесплатный PlantNet; если уверен (`top_score ≥ 0.30`) → возвращаем растение, **грибной (платный) вызов НЕ делается**;
- если пусто/слабо → прогоняем Kindwise Mushroom.id; если уверен (`top_score ≥ 0.50`) → возвращаем гриб + `safety_notice`;
- иначе отдаём слабый растительный результат (честное «не определилось»).
- `kingdom=fungi`/`plant` остались форс-оверрайдами (не обязательны).

**Проверено:** фото мухомора (`auto`) → PlantNet мимо → Kindwise `Amanita muscaria` 0.99, карточка «Мухомор красный», `safety_notice` есть. Одуванчик (`auto`) → PlantNet 0.44, грибной вызов НЕ сделан, `safety_notice` нет. Клиенту менять нечего — ты уже шлёшь `auto`.

## 2. found-state в «Рядом» (RFC §A)
`GET /api/quests/nearby?lat=&lng=&device_key=…` (новый необязательный `device_key`):
- каждый `item` несёт **`found: bool`** = этот девайс уже верно определял этот вид (lenient-матч Q1: near-tie ∪ род, по всем его определениям);
- в корне ответа — **`found_count`** (сколько из показанных найдено).
- Без `device_key` — `found:false` у всех, `found_count:null` (как сейчас).

## 3. «Знаток биотопа» — гео-привязанные значки (RFC §B)
Геопривязка = награда: засчитываются ТОЛЬКО определения **с гео, сделанные стоя в этом биотопе**
(`worldcover.biotope_at` по точке снимка), и только если вид характерен для биотопа (`plant_biotopes`).
Счётчик = разные виды (дедуп по latin_key). Тиры **Новичок/Любитель/Мастер**, пороги по богатству биотопа
(лес 5/15/40, поле/луг 5/12/30, болото/вода 3/8/18, скалы/пески/горы 3/7/15).

**Врезка в «Рядом»** (без второго запроса — точка уже знает биотоп):
```jsonc
"biotope_progress": { "biotope":"лес", "matched":6, "current_tier":1,
                      "next_need":15, "claimable_tier":1, "tiers":[…], "examples":[…] }  // null если биотоп точки не определён
```
**Отдельный прогресс:**
`GET /api/quests/biotope-progress?device_key=&biotope=лес` → та же форма, что `badge/progress` у мест
(`matched, tiers:[{tier,name,need,points}], current_tier, claimable_tier, next_need, examples`).

**Выдача значка (silent UUID, кумулятивно — без сезонного окна):**
`POST /api/quests/biotope/claim?device_key=&biotope=лес` → `{issued, tier, name, ordinal, points, granted[]}`
(идемпотентно: повтор → `issued:false, reason:"already"`). Механизм тот же, что у мест.

**Полка значков:** `GET /api/quests/badges` теперь у каждого значка есть **`kind`** = `"biotope"` или `"place"`.
У биотоп-значка: `biotope`, `tier`, `name`, `ordinal` (place/window/year = null).

**Проверено** на реальном девайсе (30 гео-определений): лес matched=6 → взят тир «новичок» (ordinal 1), повтор claim идемпотентен, на полке `kind:"biotope"`.

## Канонические ключи биотопов (для UI-иконок/названий)
`лес · луг · поле/сорное · сады/парки · кустарники/заросли · водное/прибрежное · болото/сырое ·
каменистые/скалистые склоны · пески/дюны/обнажения · горы/предгорья` (то, что отдаёт WorldCover-точка).
