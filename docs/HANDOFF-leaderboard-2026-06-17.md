**От:** мобильный агент «Что растёт». **Дата:** 2026-06-17.
Решения зафиксированы в `PLAN-quests-progression.md` (ч.2). Клиент УЖЕ зовёт эндпоинт

скрыта; как поднимешь — появится без правок клиента.

## Контракт (реализовать)
```
GET /api/quests/leaderboard?device_key=<uuid>&limit=20  →
{
  "me":  {"rank": int, "nick": str, "score": int, "badges": int} | null,
  "top": [ {"rank": int, "nick": str, "score": int, "badges": int}, … ]   // топ-`limit`
}
```
- `score` = СУММА баллов за бейджи устройства. **v1: фикс `POINTS_PER_BADGE` (предлагаю
  10) × число бейджей.** Держи начисление как функцию `badge→points`, чтобы позже
  подменить на уровневую модель (см. PLAN — ур.1/2/3 разной цены).
- `badges` = число выданных бейджей (`quest_issued_badges` по device_key).
- `rank` = плотный ранг по `score desc`; тай-брейк детерминированный (напр. по самой
  ранней `issued_at`). `me` отдаём ВСЕГДА (даже если вне топ-`limit`), `null` только если
  у устройства 0 бейджей и не хотим показывать.
- Источник — только `quest_issued_badges` (античит бесплатно; клиент счёт не шлёт).

## Ник (псевдоним)
- **Авто-ник на устройство**, человекочитаемый и анонимный (напр. «Зелёный Бегемот
  #4271»). Детерминированно из `device_key` (тогда хранить не надо) ИЛИ поле в
  `quest_devices`. Без обязательного ввода (правило silent-identity).
- Смена в настройках — через уже существующий `PATCH /api/devices/{key}/nickname`
  (если поля `nickname` нет — добавь). Клиентский UI смены ника — позже.

## Инфра
`/quests/*` уже в nginx-whitelist flora → `/quests/leaderboard` доступен без правок.

## Проверка
2 устройства с разным числом бейджей → `leaderboard` ранжирует по score; `me.rank`
у каждого корректен; новое устройство (0 бейджей) → `me:null` или score 0.
