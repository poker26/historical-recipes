# HANDOFF → backend: качество reviewed-монографа (аудит на Хмеле)

**От:** мобильный агент «Что растёт». **Дата:** 2026-06-17.
Прошёлся по эталонному Хмелю (`fb743008…`, reviewed). Выверенные LLM-поля чистые
(verdict, description, uses[].summary, compounds[].note, cautions.text — отлично). Но
часть полей всё ещё **сырые** (как был harvest). По убыванию заметности:

## A. `lead_fact` — это инструкция, а не «интересное» (ВЫСОКИЙ)
Сейчас у Хмеля:
> «Хмель (Humulus lupulus). Примените фланелевый мешочек с хмелем и влажный компресс
> (грелку, бутылку с водой, но никогда — сухую электрогрелку) по зоне поражения.»

Проблемы: (1) это **рецепт/инструкция**, а не любопытный факт; (2) **дословно дублирует
`uses[0].quote.text`** (показываем один и тот же текст дважды — в «Интересное» и в шторке
действия). Клиент рендерит это как «✦ Интересное» — выглядит странно.
**Нужно:** `lead_fact` = действительно любопытный, самодостаточный факт о растении
(этимология, история, экология, рекорд), НЕ совпадающий с первой цитатой и не являющийся
инструкцией. Если хорошего факта нет — лучше `null` (клиент скрывает блок).

## B. `uses[].indications` сырые + мусорные «действия» (ВЫСОКИЙ)
`summary` у действий чистый, но **`indications` под каждым действием — сырое со-вхождение**,
часто противоречит действию:
- `мочегонное` → «гастриты, циститы, **бессонница**, водянка…» (бессонница не сюда);
- `желчегонное` → «…**выпадение волос**…»; `бактерицидное` → «**бессонница**…».
Плюс среди действий есть **не-действия**: `"наружное применение"` (это способ, не действие)
и `"лечебное"` (пусто по смыслу).
**Нужно:** (1) дистиллировать `indications` под каждое действие — оставлять только
релевантные (как уже сделано для summary); (2) выкинуть мусорные ярлыки действий из
ACTION-словаря (`наружное применение`, `лечебное` и т.п.). Это часть чистки домена
ДЕЙСТВИЙ (Слой 1). Клиент показывает indications в шторке действия — сейчас это шумит.

## C. `harvest` «Сбор» — отдельный хендоф (СРЕДНИЙ, уже отправлен)
См. `HANDOFF-monograph-harvest-2026-06-17.md`. Клиент уже скрывает сырой свал, ждёт
`harvest.text`.

## D. `parts_used` слегка избыточен (НИЗКИЙ)
«шишка, молодые побеги, лист, лупулин, корень, корневище, смола, соцветие, побег,
подземный побег» — дубли (корень/корневище/подземный побег; побег/молодые побеги). Можно
дистиллировать до 3–5 ключевых при полировке. Не срочно.

## E. recipes-лейблы и sources (НИЗКИЙ)
- `recipes[].label` тащит хвост книги: «Антигипоксические сбор — Фитотерапия: традиции…» —
  длинно. Лучше отдать `label` = название рецепта, книгу — отдельным полем (клиент покажет
  подписью). 
- `sources` = 64 записи, вероятно с near-дублями — можно схлопнуть. Это раскрывающийся
  футер, не горит.

## Итог приоритетов
A (lead_fact) и B (indications + мусорные действия) — самое заметное после harvest, бьёт
по доверию. Всё это — дистилляция в reviewed-монографе (`reader_monograph.py`, polish) +
чистка ACTION-словаря (Слой 1). Клиентских правок не требует (кроме опц. дедупа
lead_fact↔quote — могу прикрыть на клиенте, если хочешь, пока не пофикшен бэкенд).
