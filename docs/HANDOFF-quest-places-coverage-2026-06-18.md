# HANDOFF → мобильный агент: ОХВАТ и отбор квест-мест (важно для empty-state)

**От:** backend-агент. **Дата:** 2026-06-18.
Дополняет `HANDOFF-quests-places-2026-06-17` (там только формат эндпоинтов). Здесь —
**откуда берутся места и каков охват**, чтобы UX правильно обрабатывал «мест нет».

## Как отбираются места (НЕ ручной список)
Места ингестятся автоматически из **OpenStreetMap** (`OsmIngestWorkflow` по bbox региона).
Критерии (фиксированные):
1. **Тип — только именованные зелёные/природные**: `leisure=park|nature_reserve|garden`,
   `landuse=forest`, `natural=wood`, `boundary=protected_area`. Сейчас по факту:
   **парки 122 · заповедники/ООПТ 8 · леса 4**.
2. **Есть `name`** (безымянные пятна не берём — бейджу нужно имя).
3. **Площадь ≥ 0.05 км²** (микро-дворы/скверы отброшены). Разброс 0.05 … 124.8 км²
   (Лосиный остров), среднее ~1.9 км².
4. Полигон/мультиполигон (для `ST_Contains` по GPS).

→ Принцип: **«все именованные парки/леса/заповедники ≥0.05 км² в bbox региона по OSM»**.
Покрытие зависит от OSM: если место не названо/не затегано в OSM — его у нас нет.

## ТЕКУЩИЙ ОХВАТ = МОСКВА (пилот)
**134 места, только Москва + ближнее Подмосковье** (bbox lat 55.55–55.91, lon 37.33–38.01).
Других городов ПОКА НЕТ (масс-ингест отложен).

**Следствия для UX (обязательно):**
- `places/near` за пределами Москвы → **`places: []`**. Это НЕ ошибка — покажи empty-state
  «Пока места есть только в Москве, скоро добавим другие города», а не «ничего не найдено/
  ошибка».
- Даже в Москве в радиусе пользователя может не быть места с набором на текущее окно →
  тоже пустой список, тот же empty-state.
- Не считай пустой `places/near` сетевой ошибкой.

## Как охват будет расти
Отдельный прогон `OsmIngestWorkflow(bbox)` на новый регион/город (backend-сторона) +
прогон `QuestSetBuilderWorkflow(window)` для новых мест. Дизайн на топ-40 городов готов,
включим по мере готовности. Когда добавим — те же эндпоинты просто начнут возвращать места
там; правок клиента не нужно.
