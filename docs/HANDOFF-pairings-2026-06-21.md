# HANDOFF → мобильный агент: «С чем дружит» (сочетаемость) — флагман платного слоя

**От:** backend-агент. **Дата:** 2026-06-21. Бэкенд готов и публичен. Нужна клиентская обвязка.

## Зачем
Превращает простыни рецептов в actionable-знание: для растения — с чем оно **исторически сочетается** (по реальной со-встречаемости в оцифрованных рецептах), с доказательством-рецептом. Это **grounded, не выдумано LLM** — главный «вау» и **платная фича** энтузиаста. Показывать в момент после определения / на карточке растения.

## Контракт
`GET /api/plants/{id}/pairings?category=&limit=15` (хост `flora.begemot26.ru`, публичный, zero-LLM, мгновенный):
```jsonc
{
  "plant_id": "...", "canon_id": "...",          // canon = род-хаб, если вид свёлся к роду
  "category": null,                               // эхо запроса (null = overall)
  "categories": ["настойка","отвар","чай","ликёр","бальзам","эссенция","сбор",...],  // что есть → тумблер формы
  "items": [
    { "plant": { "id","name","name_latin","photo_url","safety_level","rank" },  // tap → /plants/{id}
      "support": 82,           // в скольких рецептах вместе
      "lift": 3.9,             // во сколько раз чаще случайного
      "specific": false,       // true = high-lift, «особенная близость»
      "recipes": [ { "id","name","book","year" } ]   // ДО 3 рецептов-доказательств (book+year)
    }
  ]
}
```
- `category` опускаешь → overall; передаёшь из `categories` → срез «в настойках» (пример юзера). Тумблер формы строй из `categories`.
- Список уже **отранжирован** (общие «друзья» сверху, специфичные — с `specific:true`). Просто рендерь по порядку.

## UX (рекомендации)
- **Две интонации в одном списке:** обычные = «часто вместе · в {support} рецептах»; `specific:true` = бейдж **★ особенная близость**. Можно и двумя секциями («Частые спутники» / «★ Особая близость»).
- **Рецепт-пруф = романтика:** «встречаются в “{recipes[0].name}” ({book}, {year})» — это и доказательство, и charm. Тап → карточка рецепта.
- **Тумблер формы:** «везде / в настойках / в отварах / в чаях…» из `categories`.
- **Safety:** если у парного растения `safety_level ≥ 3` — пометь предупреждением (не предлагай мешать с опасным беспечно). См. L0-L4.
- Парный `plant.id` открывается как любая карточка (может быть род-хаб `rank:"genus"` или registry-вид — клиент это уже умеет).

## Гейтинг (платное)
Это **премиум-фича энтузиаста**. Бесплатно — превью (например, топ-1 размыто/«ещё 8 сочетаний в Premium»), полный список + срезы по формам + рецепты-пруфы — в платном. Точную линию отсечения — на твоё усмотрение/продукт.

## Что НЕ нужно от бэка
Контракт стабилен. Данные предрасчитаны (`plant_pairings`), пересчёт — наш `build_pairings.py`. У многих растений сочетаний мало/нет (честно — гейт по support); пустой `items` = «недостаточно данных», показывай мягко.
