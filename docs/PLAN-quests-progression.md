## Часть 1 — ЗАПРОС К БЭКЕНДУ (actionable): пагинация прогулки «Ещё растения рядом»

**Зачем.** Прогулка отдаёт топ-5 видов и детерминирована → когда юзер «закрыл» все 5,
продолжить нельзя (а вне зоны бейджей это вообще единственный контент). Клиент при 5/5
показывает финал-плашку и хочет кнопку **«Ещё растения рядом»**.

**Что нужно.** В `GET /api/quests/walk` добавить пагинацию по тому же ранжированию:
- параметр `count` (сколько вернуть, дефолт 5) и/или `offset` (сколько пропустить),
  **или** `exclude=latin_key,latin_key,…` (виды, что клиент уже показал) — что проще на
  iNat `species_counts` (там есть `page`/`per_page`).
- Семантика: следующая пачка по убыванию частоты, тот же адаптивный радиус/узнаваемость/
  theme-safety. Конец списка → пустой `items` (клиент покажет «рядом больше нет»).
- Бэкенд-код: `build_walk(..., target, offset?)` уже почти готов (target есть; добавить
  пропуск/страницу в `_species_counts`).

Не блокер для остального; чисто расширение существующего эндпоинта.

## Часть 2 — ПЛАН: баллы за бейджи + leaderboard

### Принципы (из проекта — не нарушать)
- **Идентичность silent UUID, без аккаунтов/PII/логина.** Leaderboard анонимный/
  псевдонимный. Ник — авто-генерируемый, опц. смена в настройках (PATCH
  `/devices/{key}/nickname` уже есть). Никакого обязательного ввода.
- **Награда = редкость/статус, инфо не гейтится.** Баллы — сопоставимый «счёт» поверх
  бейджей, не плата за контент.
- **Античит бесплатно:** баллы считает СЕРВЕР из верифицированных бейджей. Клиент
  НИКОГДА не присылает свой счёт. Фарм требует реально ходить и снимать в окне.

### РЕШЕНИЯ (зафиксированы 2026-06-17)
1. **Баллы — только за бейджи.** Никаких баллов за прогулку/первый вид.
2. **v1 — фикс за бейдж.** Будущее — **уровневые бейджи разной стоимости** (см. ниже).
3. **Leaderboard — начинаем с ОДНОГО среза** (рек.: global all-time; per-place — потом).
4. **Ник — авто + опц. смена в настройках.**
5. **Счёт копится ВЕЧНО** (без сезонного сброса; «сбросить всегда успеем»).

### v1 (минимальная стройка, когда дойдём)
- Бейдж = **фикс N баллов** (напр. 10). Счёт устройства = сумма по `quest_issued_badges`.
- **Global all-time** leaderboard. Авто-ник. Вечное накопление.
- Бэкенд: `GET /api/quests/leaderboard` → `{me:{rank,score,badges}, top:[{nick,score,
  badges}]}` (серверный агрегат); авто-ник + дефолт.
- Клиент: экран leaderboard (вход из «Прогулок»); «+10, ты #N» при выдаче; счёт на полке.

### Будущее: УРОВНЕВЫЕ бейджи (главная эволюция модели)
Сейчас бейдж бинарный (есть/нет при `target`). Новая модель — **один бейдж на место×сезон,
который ПОВЫШАЕТ УРОВЕНЬ** по числу определённых видов; стоимость растёт с уровнем.
- Пример: 5 видов → ур.1, 15 → ур.2, весь набор → ур.3. Баллы ≈ порог (5 / 15 / 30) —
  «баллы = сколько видов места освоил».
- На leaderboard место×сезон даёт баллы **высшего достигнутого уровня** (не суммируем
  уровни — иначе двойной счёт). Общий счёт = сумма по всем место×сезон.
- Это меняет бэкенд-модель бейджа: `claim` → не бинарный, а возвращает текущий **level**
  + порог следующего; прогресс уже считается (`matched/set_size`), пороги накладываются
  сверху. Клиент рисует «ур.2 → до ур.3 ещё K видов».

#### Открытые суб-решения по уровням (подумать)
- **Пороги: абсолютные (5/15/30) или относительные** к `set_size` места? Места разные
  (богатый парк 30, мелкий 8) → абсолютные сломают мелкие. Рек.: **относительные с полом**
  — ур.1 = max(5, 20%), ур.2 = target(≈60%), ур.3 = полный набор; баллы = число видов
  порога (богатые места ценнее → мотивирует исследовать).
- **Иерархия названий (нужно решить).** Варианты звания:
  - 3 ступени: **Новичок → Знаток → Мастер**
  - 4 ступени: **Новичок → Любитель → Знаток → Мастер**
  - Формат карточки без склонений: звание крупно + подпись местом —
    «**Знаток** · Битцевский парк · лето 2026» (а не «Знаток Битцевского парка» —
    склонять имена мест из OSM больно).
  - Сезон в подписи: «лето 2026» / «вторая половина июня 2026»?

### Поверхность (итог)
**Бэкенд:** points-функция (v1 фикс; позже level→points) + агрегат; `GET /quests/
leaderboard`; авто-ник. **Клиент:** экран leaderboard, показ баллов/уровня при claim и на
полке, опц. ник в настройках.

**Статус:** v1 — решено, готов писать RFC и строить, когда скажешь. Уровневые бейджи —
ждут выбора порогов + иерархии названий.
