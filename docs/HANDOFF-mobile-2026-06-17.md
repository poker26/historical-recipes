## 1. Монографы (карточки растений)

**`GET /api/plants/{id}?view=field`** — компактный дедуп-монограф для человека/приложения.
- Сейчас отдаёт **живой fallback** (агрегация на лету). Качество «как есть из данных», но структура финальная.
- Когда масс-прекомпьют Слоя-2 пройдёт (после чистки данных), тот же эндпоинт начнёт отдавать **reviewed**-монограф. `?fresh=1` форсит fallback в обход.
- Контракт `?view=field` (дедуп, Part B deepen-links: quote + `action_id` + определение вещества; «читать ещё» = client substring-match) — см. `docs/RFC` по reader-monograph + полевому клиенту. **Дефолт-view и MCP `get_plant` НЕ трогаем** — они отдают RAW (для AI-агентов); человек/приложение = `?view=field`.

**Статус прекомпьюта:** `ReaderMonographWorkflow` построен, пилот прошёл (2 опубл.), **масс-прогон НЕ запущен** — гейтится ВСЕМ Слоем 1 (идентичность/merge/действия/рецепты ещё чистятся). Генерить сейчас = запечь грязь. Поэтому: **строй против fallback, апгрейд качества придёт без изменения клиента.**

## 2. Квесты

Бэкенд построен (Фазы 1-6). Эндпоинты (`/api/quests/...`):
- **`GET /walk?lat=&lng=&month=&theme=`** — «5 видов рядом»: адаптивный радиус, узнаваемые растения, theme-safety (`theme=edible` → только нетоксичные), мост к корпусу (`plant_id=null` = монографа нет). ЖИВ.
- **`GET /badge/progress?device_key=&place_id=&window=&year=`** — прогресс бейджа. ЖИВ.
- **`POST /badge/claim?device_key=&place_id=&window=&year=`** — выдать бейдж. ЖИВ.
- **`GET /badges?device_key=`** — полка бейджей. ЖИВ.
- **`POST /set/compute?place_id=&window=`** — пересчитать ОДИН набор место×окно (админ).

**Бейдж-наборы (место×окно→виды):** `QuestSetBuilderWorkflow` **ЗАПУЩЕН СЕЙЧАС** на окно `second-half-06` (333 места Москвы), фанит iNat по местам, пишет наборы по ходу (~10-30 мин). Окна = полумесячные метки (`first-half-06` / `second-half-06`). Другие окна — по запросу.

⚠️ **Кавет:** наборы строятся на **несмёрженном** списке видов (merge Слоя-1 ещё не сделан) → возможен лёгкий дубль-шум в бейджах (один вид как 2 карточки). Не блокер для стройки UI; наборы **перегоним после merge** для чистоты.

## 4. Состояние данных — важно для клиента
- **Гербарий РАСТЁТ и идентичность НЕ финальна:** идёт чистка Слоя-1 + заливка референсов (Растительные ресурсы СССР — состав по видам). ~19 785 карточек сейчас. **Не хардкодь фиксированный список видов и не кэшируй карточки/ID надолго** — будут merge/relink.
- **Дубли и неочищенные факты** в RAW-данных останутся до merge/relink. `?view=field` дедуплицирует для показа — полагайся на него, не на RAW.
- **Фото:** ~6443 карточек без фото (нет таксона iNat / нет CC-чистого фото). Обрабатывай «нет фото» gracefully. Re-обогащение для новых карточек — позже.
- **Стабы:** часть растений без монографа/uses → в `/walk` это `plant_id=null`. Показывай вид без перехода в карточку.
