# Google Play — первая выкладка «Что растёт»

Аккаунт разработчика заведён и оплачен 9 сентября 2026. Приложение бесплатное, платежей
нет. Пакет `ru.begemot.plantid`, тот же, что в RuStore; ключ загрузки тот же
(`keystore/plantid-release.jks`, CN=begemot26).

Что делает Play, чего не делают RuStore и App Store: требует **AAB** вместо APK,
**targetSdk 36** для новых приложений с 31 августа 2026, форму **Data safety** и, для
личного аккаунта, **закрытое тестирование** перед выходом (12 тестеров, 14 дней).

---

## Что уже готово в репозитории

- `compileSdk`/`targetSdk` подняты до 36 (`app/build.gradle.kts`), сборка проходит.
- AAB: `./gradlew.bat :app:bundleRelease` → `app/build/outputs/bundle/release/app-release.aab`,
  подписан ключом загрузки. Play App Signing перепишет подпись своим ключом, это норма.
- Тексты листинга: `docs/STORE-LISTING.md` (описание, ключевые слова, скриншоты 1290×2796
  в `docs/store-assets/framed/`, иконка из проекта).

## Что делается руками в Play Console (один раз)

1. **Создать приложение**: название «Что растёт», язык по умолчанию русский, тип
   «Приложение», бесплатное. Через API создать приложение нельзя.
2. **Play App Signing**: при первой загрузке AAB выбрать «Google управляет ключом подписи»,
   наш jks остаётся ключом загрузки. Ничего экспортировать не нужно.
3. **Политика конфиденциальности**: URL тот же, что в App Store и RuStore.
4. **Data safety** (раздел «Безопасность данных»). Честные ответы для нашего приложения:
   - Собираем: **геолокацию** (примерную и точную, для «что растёт рядом» и прогулок,
     не обязательно), **фото** (снимок для определения, уходит на сервер), **идентификатор
     устройства** (тихий UUID, не рекламный), **пользовательский контент** (ник, аватар,
     находки в ленте). Не собираем: имя, e-mail, телефон, контакты, платежи, историю
     браузера, рекламный ID.
   - Данные шифруются при передаче (HTTPS). Удаление: пользователь может удалить находку
     из истории, удаление стирает и архивный файл на сервере.
   - Передача третьим лицам: фото уходит внешнему определителю (PlantNet) — указать как
     «передаётся для функциональности приложения».
5. **Разрешения**: в манифесте только `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION`
   (только на переднем плане, форма про фоновую геолокацию не нужна), `POST_NOTIFICATIONS`,
   `INTERNET`, `ACCESS_NETWORK_STATE`. Разрешения на камеру нет: снимок через системный
   интент. Рекламного ID нет — в декларации отметить «не использует».
6. **Возрастной рейтинг**: опросник IARC. Ответы: нет насилия, нет сексуального контента,
   нет азартных игр, есть пользовательский контент (ники и лента находок) с модерацией,
   есть обмен геолокацией с другими пользователями — нет (координаты никогда не
   показываются, только название парка). Ожидаемо 3+ / «Для всех».
7. **Целевая аудитория**: 13+ (не детское приложение), чтобы не попасть под семейную
   политику.
8. **Категория**: Образование. Контакты разработчика: e-mail для пользователей и сайт
   `https://botanik.fun`.
9. **Листинг**: короткое описание (≤80) и полное (≤4000) из `STORE-LISTING.md`,
   иконка 512×512, feature graphic 1024×500 (его у нас НЕТ — нужно сделать один баннер),
   скриншоты телефона: минимум 2, наши 6 кадров 1290×2796 подходят (соотношение 9:16
   в допуске).

## Личный аккаунт или организация

Если аккаунт **личный** (создан после ноября 2023): перед production обязателен
closed test — трек «Закрытое тестирование», список e-mail не меньше 12 человек, все
должны принять приглашение и оставаться в тесте 14 дней подряд. Потом на странице
Dashboard кнопка «Подать заявку на доступ к production», Google рассматривает ещё
несколько дней. Тестеров есть из кого набрать: у приложения 315 устройств за лето.
Если аккаунт **организации**: этого шага нет, можно сразу в production.

## Автоматизация после первой выкладки

Загрузка следующих версий через Google Play Developer API: в Console «Настройки →
Доступ к API» создать сервисный аккаунт, дать ему права на релизы, ключ JSON положить
рядом с `rustore-credentials-release.json` (gitignored). Тогда AAB + «что нового»
уходят скриптом, как в RuStore. Первую загрузку всё равно делать руками: до неё
Console не даёт включить API для приложения.

## Верификация разработчика Android (не Play, а вся платформа)

С 30 сентября 2026 в Бразилии, Индонезии, Сингапуре и Таиланде, с 2027 глобально,
установка любого приложения на сертифицированный Android требует верифицированного
разработчика, включая RuStore и sideload. Аккаунт Play закрывает это той же личностью.
