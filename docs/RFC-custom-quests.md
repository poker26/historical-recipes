# RFC: «Закажи свой квест» — премиум-фича кастомных квестов по точке

Status: Proposed (2026-06-21). Premium (платная) фича. Расширение квест-движка
([[RFC-quests]], [[RFC-biotope-mastery]]), НЕ новая архитектура.

## Мотивация
Сценарий юзера: «хочу **пройти квест** именно там, где я сейчас (живу на даче), а
доступных квестов тут нет». Текущий движок строит квест-места только из именованных
OSM-полигонов (парки/леса/заказники) с достаточной плотностью iNat → в глуши/на даче
квестов нет вовсе. Премиум-фича: юзер **«заказывает» новый квест в своей местности**
(любой биотоп, не обязательно лес). On-demand расчёт = реальная стоимость (iNat+GBIF+
WorldCover+set-build) → оправдывает плату.

## Решения (юзер, 2026-06-21)
1. **Геометрия = круг с привязкой к биотопу.** Радиус-круг вокруг точки юзера (0.5/1/2 км,
   дефолт 1 км), обрезанный по патчу доминирующего/самого богатого ПРИРОДНОГО биотопа
   (WorldCover/OSM-landuse) внутри круга — «квест по поляне/опушке, где ты стоишь», а не
   «деревня + дорога + поле».
2. **Виды: ожидаемые включаем В ЦЕЛЬ** (не только бонус). Набор = Слой 1 «точно растёт»
   ∪ Слой 2 «ожидается для биотопа в регионе», слитые в один target — чтобы квест был
   ВСЕГДА, даже в глуши. У каждого вида — флаг уверенности (`confirmed`/`expected`) для
   честной подписи в UI (★ «ожидается»), но оба считаются к бейджу.
3. **plantarium.ru — да, как Слой-2 регион-чек-лист, on-demand по одному.** Лицензия
   (юзер проверил): фото НЕ берём (права у авторов), текст/факты-присутствия можно с
   **атрибуцией**; **массовый парсинг запрещён** → тянем по запросу, скромным числом
   запросов на один заказанный квест. Картинки карточек — всегда iNat/GBIF.

## A. Геометрия
- Вход: точка юзера + выбранный радиус (0.5/1/2 км).
- WorldCover в точке + в круге → классы биотопов. Дача часто = built-up/cropland →
  НЕ берём застройку как биотоп: выбираем самый видо-богатый ПРИРОДНЫЙ класс в круге
  (лес/луг/опушка/вода/…) ИЛИ даём юзеру выбрать патч, если их несколько.
- Полигон = круг ∩ {клетки выбранного класса} (маска по растру), упрощённый в
  multipolygon. Кап на площадь (walkable). Показать на карте «перед заказом» для
  подтверждения.
- Хранить как ad-hoc `quest_places` (источник `custom`, owner = device_key), чтобы
  переиспользовать `place_set`/`badge_progress`/claim как есть.

## B. Источник видов (слоями, с флагом уверенности)
**Слой 1 — «точно растёт здесь» (точечные находки в полигоне):**
- iNat `species_counts` (как сейчас), но окно ослабить: весь сезон (не полумесяц) +
  больше лет, радиус расширять при пустоте.
- **GBIF occurrences** в bbox/полигоне (Plantae, последние десятилетия, с координатами).
  Лучший «больше данных» источник: агрегирует iNat + гербарии + съёмки, бесплатный API,
  чистая лицензия (CC0/CC-BY), хорошее покрытие РФ за счёт гербариев. Слияние по `_latin_key`.

**Слой 2 — «ожидается здесь» (когда Слой 1 < цели):**
- reverse-geocode точки → админ-регион + WorldCover-биотоп.
- Кандидаты = «характерные для биотопа» (`plant_biotopes`) ∩ «известные в регионе».
- «Известные в регионе»: GBIF по широкому радиусу + наш корпус + **plantarium регион-чек-лист**
  (флористический список региона; on-demand, по одному, с атрибуцией).
- Слить со Слоем 1 в target (решение юзера), сохранив `confidence=expected`.

**Картинки** карточек — iNat/GBIF, никогда plantarium.

## Переиспользование существующего
`compute_species_set(force=True)` уже обходит порог плотности; есть `worldcover.biotope_at`,
`plant_biotopes`, `_latin_key`/`resolve_latin_to_plants`, машина place×window-наборов и
выдачи бейджей. Кастом-квест = (1) построить полигон, (2) ad-hoc `quest_place(source=custom)`,
(3) `compute_species_set` с ослабленными параметрами + GBIF + Слой-2-фолбэк, (4) бейджи как
обычно. Новый код: GBIF-клиент, plantarium регион-чек-лист (on-demand), биотоп-маска полигона,
reverse-geocode, премиум-гейт/оплата, клиентский «заказ квеста».

## Премиум-обвязка
- Модель: 1 бесплатный кастом-квест (тизер) → дальше платно (по квесту или подписка N/мес).
- Оплата: РФ-рельсы (ЮKassa/CloudPayments/СБП), НЕ Stripe — см. [[historical_recipes_monetization]].
- Анти-абуз: кап площади/радиуса, рейт-лимит, **кэш по geohash** (соседи по даче
  переиспользуют расчёт), один заказ = скромное число GBIF/plantarium-запросов.
- Честность: бейдж считает и confirmed, и expected, но подпись ★ «ожидается» отличает их;
  дисклеймер «часть видов — ожидаемые для биотопа в вашем регионе, могут не встретиться».

## Фазы сборки
1. **Геометрия + ad-hoc place**: радиус-круг + биотоп-маска (WorldCover) → `quest_place(custom)`;
   клиент: «Заказать квест здесь» → выбор радиуса → превью полигона на карте → подтвердить.
2. **GBIF-аугментация Слоя 1**: GBIF occurrences-клиент, слияние с iNat в `compute_species_set`.
3. **Слой 2 expected**: биотоп×регион из корпуса + GBIF-региональный; флаг confidence в наборе/UI.
4. **plantarium регион-чек-лист** (on-demand, по одному, атрибуция) — добор Слоя 2 для глухой РФ.
5. **Премиум-гейт + оплата** (ЮKassa/СБП), тизер + кэш по geohash, анти-абуз.

## Открытые вопросы
- Какой именно природный биотоп брать на даче, если их несколько в круге (авто-самый-богатый
  vs выбор юзера)?
- Параметры GBIF (года/качество/гео-точность-фильтр); дедуп iNat↔GBIF.
- Что именно парсить на plantarium (регион-флор-список vs per-species присутствие) + кэш + атрибуция.
- Цена и единица (за квест vs подписка); тизер-лимит.
- Платёжная интеграция (ЮKassa vs СБП) — отдельная задача.
