# RFC — «Знаток биотопа»: награда за усилие + found-state в «Рядом»

**Дата:** 2026-06-19. **От:** мобильный (по фидбеку юзера). **Кому:** backend-агент.
**Статус:** одобрено юзером (геопривязка подтверждена). Бэк кладёт контракт → клиент верстаю я.

## Ядро (зачем)
Сейчас слиплись ДВЕ оси награды:
- **Ширина (пассив):** увидел растение, снял, «наблюдение зачтено» → двигает уровень «натуралиста».
- **Глубина по месту (усилие):** в режиме «Рядом»/квест-место тебя послали найти ИМЕННО клевер в этом
  поле — ты пошёл и нашёл. Это работа. Сейчас за неё сухое «зачтено» в никуда → разочарование.

Развести и за вторую — поощрять явно. Уровень = сколько разных видов встретил вообще; «Знаток леса» =
сколько лесных видов нашёл **находясь в лесу** (геопривязка = награда за то, что реально пошёл туда).

## A. found-state в «Рядом» (минимум — убивает тупик «зачтено»)
Сейчас `/quests/nearby` НЕ трекает found (поле `found` всегда false → карточка не меняется).
- На каждом item в `/quests/nearby` возвращать `found: bool` = этот device уже правильно определил
  этот вид (по identifications этого device_key, тем же зачётом, что и квесты: lenient-матч Q1
  `score≥0.85·top` или род). Опционально геогейт: засчитывать found, если снято в том же биотопе.
- Клиент (я): карточка → «✓ Найдено» (галка, фото приглушено, уходит вниз), сверху «Найдено N из 5».

## B. Значки «Знаток биотопа» (геопривязанные, везде)
Переиспользует готовое: домен **`plant_biotopes`** (растение↔биотоп, 18 типов, см.
[[historical_recipes_biotope_domain]]) + `/quests/nearby` уже зовёт **`biotope_at(lat,lng)`**
(WorldCover, без egress) + тир-паттерн квест-значков (Новичок/Любитель/Мастер).

**Прогрессия (геопривязка обязательна):** при КАЖДОМ определении с гео (`identifications.lat/lng`),
которое уверенно совпало с видом (lenient-матч Q1):
1. определить биотоп точки: `biotope_at(lat,lng)`;
2. если вид характерен для этого биотопа (`plant_biotopes` содержит plant↔биотоп);
3. → засчитать вид в счётчик **(device_key, biotope)** = множество РАЗНЫХ видов (дедуп по latin_key).

Тиры на биотоп: **Новичок / Любитель / Мастер** (напр. 5 / 15 / 40 характерных видов). Пороги
тюнятся ПО РАЗМЕРУ биотопа (лес богатый → планка выше, болото беднее → ниже). Мастер = редкий флекс
(это фича, а не баг — «в поле много видов» = высший грейд должен быть тяжёлым).

**Где засчитывается:** ЛЮБОЕ effortful-определение по локации — и «Рядом», и «Снять» из квест-места
(любой кадр с гео, попавший в характерный вид биотопа). Обычная съёмка без гео — НЕ двигает (только
уровень натуралиста).

**Хранение:** по образцу `quest_issued_badges`, badge_id = `biotope:<key>` (без сезонного окна v1 —
мастерство кумулятивно; сезонность можно добавить позже). Выдача тиров + silent-award как у мест.

**Контракты для клиента (предложение):**
- `GET /quests/biotope-progress?device_key=&biotope=` → `{biotope, matched, tiers:[{tier,name,need}],
  current_tier, claimable_tier, examples?}` (как `badge_progress` у мест).
- Прогресс текущего биотопа отдавать прямо в `/quests/nearby` (раз он уже знает биотоп точки) —
  `{... , biotope_progress:{biotope, matched, next_need, tier}}` — чтобы «Рядом» сразу показал
  «🌲 Знаток леса 7/15» без второго запроса.
- Выдача значка — тем же механизмом claim/issue, что у квест-мест (silent UUID, без коорд.).
