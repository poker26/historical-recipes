# PLAN: Очистка данных («линтер гербария») — исполняемая дорожная карта

Статус: **утверждён 2026-06-09** (поверх `RFC-data-quality.md`, Option A).
Этот документ — рабочий план с чеклистами; RFC — обоснование и каталог чеков.

## Принятые решения (2026-06-09)

1. **Фаза 0.5 — да**: до диагностического свипа дозагружаем всё запланированное
   (27 zip Tier-1 + Tier-2 ≈ 42), чтобы свип считал финальную картину корпуса.
2. **Гейт — гибрид**: открытый **P0 → жёстко скрыт** из MCP/паблика (абсурд с
   бейджем — всё равно абсурд); **P1 → виден с бейджем** «данные проверяются».
3. **Таксономия-эталон**: iNat первичный (RU-вернакуляры, уже подключён через
   trusttunnel) + GBIF как опора accepted-name/kingdom + MycoBank для грибов.
4. **Фаза 0 стартует немедленно**, параллельно с дрейном корпуса — строительство
   инфраструктуры не требует паузы загрузки (данные не трогает).

### Фаза 0 — фундамент (параллельно с дрейном корпуса) — ЧАСТИЧНО ✅ 2026-06-09
- [x] Миграция `014_data_quality_findings` (применена на проде, head 013→014).
      Модель `app/models/data_quality.py:DataQualityFinding`, uniq `(check_id, entity_id)`.
- [x] Каркас: `app/services/data_quality/framework.py` — `@validator`-реестр,

      (confirmed/dismissed/fixed не воскрешаются) + старение в `stale`. Защитный

- [x] Эндпоинты `POST /api/quality/sweep`, `GET /findings|summary|checks`
      (`app/routers/quality.py`). v1 синхронный (чеки — быстрый SQL).
- [x] Первые валидаторы (БЕЗ внешней истины, чтобы доказать движок):
      `alias.collision` (P0) и `domain.recipe_is_monograph` (P1, auto).
      **ПЕРВЫЕ ЦИФРЫ свипа: alias.collision = 1305 P0, recipe_is_monograph = 30 P1.**
- [ ] `DataQualitySweepWorkflow` (Temporal, очередь `dispatcher`) — отложено
      (синхронного эндпоинта пока хватает; нужен для расписания/долгих внешних чеков).
- [ ] Резолвер внешней истины: GBIF + iNat (+ MycoBank), кэш по образцу
      `inat_taxon_cache`. — СЛЕДУЮЩЕЕ.
- [ ] P0-сид валидаторы на внешней истине: `identity.name_vs_latin`,
      `identity.kingdom`, `index.qdrant_drift`, `identity.headnoun_collision`.
- [ ] Новые (находки 2026-06-08/09):
      - `identity.headnoun_collision` — сущности БЕЗ латыни («соль», «бальзам»):
        имя = родовая голова + определение; латин-якорь неприменим; ключ
        идентичности = полная фраза; запрет alias-захвата по голой голове.
        Примеры: plants/2eac2a4b (соль повар./калия/морфина в одной карточке),
        recipes/5779d627 (Итальянский бальзам ↔ линк на Бальзам мускатный).
        Кандидаты голов — SQL: головы-существительные с >N разными определениями;
        финальный список подтверждает юзер.
      - `domain.recipe_is_monograph` — fake-рецепт из монографии (спека в памяти:
        category='сбор' + имя=вид + ингредиенты-компаунды), авто-purge.

### Переупорядочивание после ручного разбора (2026-06-10)
Разбор реальных карточек уточнил приоритеты внутри этапов (см. память
`historical_recipes_data_quality_linter`):
- **Этап A (сущности) переупорядочен:** (A1) OCR-битые имена/латынь = КОРЕНЬ химер и
  кривой линковки → чинить ПЕРВЫМИ; (A2) `identity.chimera`/over-merge (несколько
  видов/латыней в одной карточке: «ГОЛУБИКА(ЧЕРНИКА,БРУСНИКА)», сага+Гирча) — НОВЫЙ
  класс, не было; (A3) обобщить trap-карточки в «это вообще растение?» (latin/GBIF+LLM),
  не список имён.
- **Этап B (связи) получает реальный чек:** `xref.ingredient_link_validity` — сахар→
  солодка, вода→«туффах май», брусника→мердж — alias.collision это НЕ ловит. LLM-судья
  грунтится на `original_text` рецепта.
- **Provenance:** цепочка до скана есть (BookPage.image_path); кандидат-фича — показ
  фрагмента оригинала юзеру.
