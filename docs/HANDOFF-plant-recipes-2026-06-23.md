# HANDOFF → мобильный агент: «Что приготовить» — флагман-«сделай это»

**От:** backend-агент. **Дата:** 2026-06-23. Бэкенд готов и публичен. Нужна клиентская обвязка.

## Зачем
Главный actionable-слой энтузиаста: для растения — **что из него реально приготовить** (отвар, настой, чай, сироп, варенье, наливка, маска…), с **дословным историческим рецептом** и источником (книга + год). Не выдумано LLM — взято verbatim из оцифрованного корпуса (53k рецептов, grounded). Это пара к «С чем дружит»: там — *с чем сочетать*, здесь — *что сделать прямо сейчас*. Показывать на карточке растения и сразу после определения по фото («ты нашёл крапиву → вот что из неё делают»).

## Что под капотом (чтобы доверять списку)
Триаж (`recipe_triage`, zero-LLM) разнёс корпус: оставлены только **реальные домашне-выполнимые** рецепты (`home_doable`, 43 092 / 53 111 = 81%), отсеяны промышленные процедуры, монографии-замаскированные-под-рецепт и обрывки. Внутри — `procedure_score` (есть количество + глагол-действие = настоящий пошаговый рецепт); дозировочные «дампы» формата «Растения и грибы Сибири» (МКБ-коды + дозы без процедуры) демотированы вниз и НЕ помечены `step_by_step`.

## Контракт
`GET /api/plants/{id}/recipes?kind=&limit=12` (хост `flora.begemot26.ru`, публичный, zero-LLM, мгновенный):
```jsonc
{
  "plant_id": "...",
  "kinds": ["food","medicinal","cosmetic","other"],   // что есть у этого растения → тумблер вида
  "items": [
    { "id": "...",                     // tap → GET /api/recipes/{id} (полный рецепт)
      "name": "Отвар из корней шиповника при камнях в почках",
      "category": "отвар",             // исходная категория-форма (может быть null)
      "kind": "medicinal",             // medicinal | food | cosmetic | other
      "n_ingredients": 1,              // сколько растений в рецепте (1 = это растение — главное)
      "step_by_step": true,            // есть количества + шаги (vs дозировочная справка) → бейдж
      "book": "Лекарственные растения: справочное пособие",  // источник (может быть null)
      "year": 1988,                    // год (может быть null)
      "text": "Залить 1 столовую ложку измельчённых корней 400 мл кипятка. Варить 15 минут…",
      "truncated": false               // true = текст обрезан на 700 симв., полный через /recipes/{id}
    }
  ]
}
```
- `kind` опускаешь → все формы вперемешку (уже отранжированы); передаёшь из `kinds` → срез «только еда» / «только лечебное» / «косметика».
- Список уже **отранжирован**: настоящие пошаговые рецепты сверху → где растение главное (меньше ингредиентов) → с более содержательным текстом. Просто рендерь по порядку.
- Матчинг по **роду-семье**: карточка вида подтянет и рецепты рода-хаба; карточка рода — рецепты всех видов. Пустой `items` = «рецептов в корпусе нет», показывай мягко.

## UX (рекомендации)
- **Карточка рецепта = заголовок + дословный текст + ссылка-источник.** `text` — это сам рецепт verbatim; рендерь как есть (моноширинно/цитатой — это исторический документ, в этом charm). `truncated:true` → «читать полностью» → `GET /api/recipes/{id}`.
- **Бейджи:** `step_by_step:true` → **✓ пошаговый**; `kind` → иконка (🍵 чай/настой, 🍯 еда, 💄 косметика). Дозировочные справки (`step_by_step:false`) — ниже, без галочки.
- **Тумблер вида** из `kinds`: «всё / приготовить (food) / лечебное / косметика».
- **Источник = доверие:** «{book}, {year}» под рецептом. Это не выдумка ИИ — это книга. Подчёркивай.
- **Safety:** уровень опасности берёшь с карточки растения (L0–L4), не из рецепта. Если растение `safety_level ≥ 3` — общий дисклеймер над списком рецептов («готовь с осторожностью, см. предупреждение»). Per-рецепт-safety пока нет.
- Связка с «С чем дружит»: на карточке рецепта с `n_ingredients > 1` можно подсветить второй ингредиент как «сочетание» (см. HANDOFF-pairings).

## Гейтинг (платное)
Премиум-энтузиаст-фича в одном ряду с pairings/insights. Бесплатно — превью (топ-1–2 рецепта + «ещё N в Premium»), полный список + срезы по `kind` + полные тексты — в платном. Точную линию — на продукт.

## Что НЕ нужно от бэка
Контракт стабилен. Данные предрасчитаны (`recipes.recipe_kind/is_recipe/home_doable/procedure_score`), пересчёт — наш `materialize_recipe_triage.py`. `text` уже обрезан до 700 симв.; полный рецепт + ингредиенты — через существующий `GET /api/recipes/{id}`.
