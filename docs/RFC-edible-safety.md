# RFC: Безопасность едока — ordinal-шкала съедобности/опасности (замена is_toxic)

Статус: draft (для нас; не в проде). Дата: 2026-06-18.
Связано: `Plant.is_toxic`, `PlantCulinaryUse.edibility`, `plant_toxicities`,
RFC-data-quality, [мастер-план Слой-1]. Мотиватор (юзер): «главный вопрос в лесу —
не умру ли я / мой ребёнок, если это съем».

## 1. Проблема: бинарный is_toxic — неправильная форма

`is_toxic` (boolean) не отвечает на вопрос едока — он только пугает или ложно
успокаивает. Хуже — он ставится от ЛЮБОГО упоминания токсичности:

- **Анис** `is_toxic=true`, потому что «эфирное масло ядовито для мелких птиц,
  убивает голубей, губит моль» — токсичность к ЖИВОТНЫМ, к человеку ноль.
- **Купырь лесной** был `is_toxic=true` от одной хедж-фразы «по некоторым данным…»
  (книга «Полезные растения Западной Сибири») при молчании прочих источников;
  настоящая причина страха — путаница с болиголовом.

Масштаб (2026-06-18): **2488** видов `is_toxic=true`; **798** из них одновременно
имеют съедобную `culinary_use` (конфликт); из 6136 токсик-строк **1131 про
животных**, **656 хедж-язык** (~29% слабые/нерелевантные для человеческого флага).

И **обратная ошибка той же тяжести**: `is_toxic=false` стоит у всего, про что
источники молчат → читается как «зелёный свет». Для safety-продукта отсутствие
данных НЕЛЬЗЯ выводить в «безопасно».

## 2. Модель: ordinal «уровень безопасности едока»

Один градиент «что будет, если съесть» (worst-case для едока):

| Ур. | Метка | Критерий | Примеры |
|---|---|---|---|
| **L1** | ✅ съедобно | едят как еду без оговорок | малина, сныть |
| **L2** | ⚠️ условно съедобно | не умрёшь, но нужна обработка / невкусно | орляк, грузди |
| **L3** | ☢️ опасно / дозозависимо | мало = лекарство, много = беда; «не еда» | ландыш, чистотел, наперстянка |
| **L4** | ☠️ смертельно | не трогать, не пробовать | цикута, болиголов, бледная поганка |
| **L0** | ❓ нет данных | НЕ выводить безопасность из молчания → «не ешь» | — |

`is_toxic` становится ПРОИЗВОДНЫМ (≈ level ≥ L3), не первичным.

## 3. Три уточнения, без которых шкала не отвечает на «не умру ли»

1. **Worst-case, не средняя токсичность + part-specifics.** Ревень: черешок
   съедобен, лист ядовит. Уровень сопровождается «какие части съедобны / какие
   опасны».
2. **Опасный двойник — главный убийца.** Не сам яд, а ПУТАНИЦА (Купырь↔болиголов,
   съедобный гриб↔бледная поганка). Отдельное поле «похож на смертельный X».
   Именно из-за двойника Купырь и был ложно помечен.
3. **Консервативный дефолт.** При неопределённости — ПОВЫШАЙ уровень. Лучше зря
   предупредить (L3), чем пропустить (L4→L1). Молчание → L0, не L1.

## 4. Что классификатор обязан отфильтровать
- **Токсичность к НЕ-человеку** (птицы/рыбы/скот/насекомые/моль) не поднимает
  человеческий уровень (анис → L1/L2).
- **Хедж без корроборации** (один «считается ядовитым» против многих молчащих,
  без симптомов/тяжести) не даёт L4; max L2-L3 + пометка.
- **Заведомо смертельные** (anchor-список) — жёсткий L4, LLM НЕ вправе понизить.

## 5. Данные, на которых строим
- `PlantCulinaryUse.edibility` — per-часть {съедобно / условно-съедобно /
  несъедобно / ядовито} (19371/795/187/126 + OCR-варианты «съедобна/sъедобно/
  едальна» → нормализовать). Покрытие широкое (через кулинарные факты).
- `plant_toxicities` — строки {toxic_parts, symptoms, severity, original_text}.
- `Plant.is_toxic` — текущий булев (over-set, рекомпьютим).
- `medicinal_uses` (есть лекарственное → намёк на L3 дозозависимость).

## 6. Деривация уровня
1. **Anchor смертельных** (латынь): Cicuta, Conium, Aconitum, Atropa, Hyoscyamus,
   Datura, Colchicum, Digitalis, Daphne, Veratrum, Ricinus, Nerium, Taxus,
   Convallaria(L3-L4), Amanita phalloides/virosa, Galerina… → L4, override.
2. **Реклассификация токсик-строк** (rule+LLM): мишень человек/животное; сила
   смертельно / дозозависимо / хедж; → human_severity.
3. **Сигналы съедобности**: culinary `съедобно` + нет серьёзной токсичности →
   L1/L2; несъедобно (не ядовито) → L1-по-безопасности (не еда, но не убьёт).
4. **LLM-синтез** карточного уровня из (anchor, токсик-строки, edibility,
   medicinal, латынь) + правило консервативного повышения → `safety_level`,
   `edible_parts`, `dangerous_parts`, `deadly_twin`.

## 7. Хранение
Карточные поля на `plants` (или таблица `plant_safety`): `safety_level` (0-4),
`edible_parts` (text[]), `dangerous_parts` (text[]), `deadly_twin` (text|null),
`safety_rationale` (text), `safety_source` (atrib). Нормализованная
`PlantCulinaryUse.edibility` (OCR-чистка) питает L1/L2.

## 8. Стройка (durable-свип, как биотоп/род)
1. Нормализовать `edibility`-значения (OCR-варианты → 4 каноничных) — дёшево.
2. Anchor-список смертельных (латынь) — ручной, версионируемый.
3. Реклассификатор токсик-строк (человек/животное/хедж/смертельно) — rule+LLM.
4. Durable `EdibleSafetyWorkflow` (commit-per-plant, resume): по каждому виду →
   уровень + поля; anchor-override; консервативный гейт. Идемпотентно.
5. Рекомпьют `is_toxic` из уровня (≥L3) — обратная совместимость.
6. QA-чек: L1 при наличии L4-токсик-строки; L0 не выводить как safe; конфликт
   edible+L4.

## 9. Интеграция
- `?view=field` + монограф: показывать **уровень (иконка) + двойник + part-specifics**
  как ПЕРВЫЙ блок (это главный вопрос едока). Гейт монографов — после этого свипа
  (safety-критично, нельзя переделывать).
- MCP `search_plants`/`get_plant`: `safety_level` + `deadly_twin`; фильтр edible
  → level ≤ L2.
- Хэндофф мобиле (UI красный/жёлтый/зелёный + ❓).

## 10. Открытое
- L3 vs L4 граница (ландыш = L3 «дозозависимо» или L4? — по летальности при
  бытовом съедении). Anchor решает спорные.
- Грибы: своя специфика двойников (бледная поганка) — общий механизм тот же.
- Нужен ли L0 отдельным значением или null = L0 по дефолту (склоняюсь: явный 0).
