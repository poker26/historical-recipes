# HANDOFF → мобильный агент: биотопы («где растёт») в карточке + фильтр

**От:** backend-агент. **Дата:** 2026-06-17.
Новое структурное знание — **биотоп** растения (среда обитания), нормализованный из
текста в 18 контролируемых меток. Чипы идут УЖЕ СЕЙЧАС (живой `?view=field`, не ждут
reviewed-монографа); проза-`summary` добавится в reviewed-монографе позже.

## 1. Блок `habitat` в `GET /api/plants/{id}?view=field`
```jsonc
"habitat": {
  "biotopes": [ {"key": "берега водоёмов", "group": "влажное"},
                {"key": "лес смешанный",   "group": "лес"} ],   // чипы (детерминированы)
  "regions": ["Крым", "Кавказ", "средняя полоса"],               // география (сырой текст пока)
  "summary": "Растёт по берегам рек и в смешанных лесах."        // ТОЛЬКО в reviewed-монографе; иначе нет
}
```
- `biotopes[]` — `{key, group}`. **`group` ∈** `лес · открытое · влажное · субстрат · рельеф · антропогенное · прочее` — рисуй чипы СГРУППИРОВАННО, иконку на группу (🌲 лес · 🌿 открытое · 💧 влажное · 🪨 субстрат · ⛰ рельеф · 🏡 антропогенное).
- Блок ОПЦИОНАЛЬНЫЙ (нет местообитания → нет `habitat`). `summary` опционален (нет → не рендерь прозу, покажи только чипы+regions).
- Лес 2-уровневый: общий `лес` если тип не указан, иначе подтип (`лес лиственный/хвойный/смешанный`). Показывай как есть.

## 2. Полный словарь + счётчики: `GET /api/plants/biotopes`
```jsonc
{ "biotopes": [ {"key":"лес","group":"лес","count":N}, … ] }   // 18 меток + живой счётчик растений
```
Для экрана фильтра «где искать» (чипы с числом видов).

## 3. Обратный поиск / «другие растения биотопа»: `GET /api/plants?biotope=<key>`
Стандартный list-эндпоинт + фильтр по биотопу (комбинируется с `q`/`kingdom`/`edible`/…).
Юзкейсы: фильтр «что растёт на лугу»; в карточке — «ещё растения этого биотопа» (тапнул чип → список).

## Рендер (рекомендация)
Секция **«Местообитание / Где искать»**: чипы по группам (иконки) → строка `regions` («Встречается: …») → проза `summary` (если есть, reviewed). Чип тапается → `?biotope=key` список. Логично рядом со «Сбором» (harvest): **где** (биотоп) + **когда/как** (harvest) = полевой блок.

## Что ещё придёт (не сейчас)
- **summary-проза** в чипах — при масс-генерации reviewed-монографов (гейт = чистка Слоя-1).
- **Квест-связка** «биотоп → найти в Y рядом» — нужна половина (b): GPS→биотоп через **OSM landcover** (предрасчёт био-зон мест `quest_places`). Клиент уже на OSM + шлёт GPS — не хватает landcover-слоя на бэке. Отдельный этап.
- `regions` сейчас сырой текст (длинные строки из источников) — позже нормализуем в короткую географию.
