# RFC: «Что растёт рядом» — базовый слой (cold-start), а не ещё одни квесты

**Статус:** проектирование, смена приоритета. **Дата:** 2026-06-18.
Отменяет place-центричный приоритет (`HANDOFF-quest-places-coverage`, place-biotopes как
самоцель). Это и хендоф бэкенду (раздел «Что нужно от бэка»).

## Зачем (что пошло не так)
Мы вложились в **premium-узкий слой**: ингест именованных парков по OSM (134 места, ТОЛЬКО
Москва) + биотопы **места** (`/place/{id}/biotopes`). По сути это **продублировало механику
квестов** (те же наборы видов, но привязанные к полигону), и **не сдвинуло** главный вопрос:
**что видит любой пользователь на первом экране, если рядом нет квеста.** А это — абсолютное
большинство (вне Москвы или просто не в именованном парке ≥0.05 км²). Покрытие мест **никогда
не накроет земной шар**, и пустое «квестов рядом нет» — это не функция, это заглушка.

## Принцип (мерка для любого клиентского экрана)
Маленький · ранжированный · с фото · actionable · **выведен из локации**. Без счётчиков,
дампов корпуса и пустых «ничего нет». Если экран не отвечает «зачем он мне здесь и сейчас» —
он не выходит.

## Базовый слой (КАЖДОМУ, ВЕЗДЕ): «Рядом с тобой — 5 растений»
Первое, что даёт пользу сразу после установки и **без квест-датасета**: 5 растений, которые
реально встречают рядом — фото + название + «найди и определи». Живёт на Home (карточка
«Рядом с тобой») и заполняет пустое состояние Квестов.

- **(а) GPS → iNat `species_counts`** (наш живой `build_walk`). Строится **сейчас**, клиентом,
  без нового бэка. Ранг по частоте = «самые распространённые». Риск: радиус **смешивает
  биотопы** (я в поле — а наблюдения в лесу за 20 км → выдача «лесная»).
- **(б) GPS → OSM landcover тайла → биотоп точки → характерные виды биотопа×региона**. Точнее
  под «здесь». **Переиспользует машинерию OSM→биотоп**, которую бэк уже сделал для полигонов-
  мест — нужно навести её на **произвольную точку**, а не только на московские парки.
- **Синтез (целевое): (б) как фильтр поверх (а).** Знание биотопа точки отсекает «лесные» виды,
  когда ты в поле → чинит риск (а). Список = iNat-частота ∩ биотоп-уместность, топ-5.

### Как генерить «5 характерных» (суть б)
Гибрид, по убыванию надёжности:
1. iNat `species_counts` по точке (живая локальная частота) →
2. отфильтровать видами, **уместными биотопу** точки (биотоп из OSM ∩ наши `biotope`-теги вида) →
3. топ-5: **с фото**, дедуп, **предпочесть виды из нашего корпуса** (тап → монограф).
Так список ранжирован реальной частотой И сужен до «того, что под ногами здесь».

## Premium-слой (где есть покрытие) — обогащение, НЕ база
Места-квесты + значки + фильтр «по средам места» остаются — но как надстройка ПОВЕРХ базы там,
где OSM-покрытие есть. **Перестаём гнать ингест городов как путь к массовой полезности** — это
не база. База — живой «рядом».

## Что нужно от бэка (хендоф)
1. **GPS→биотоп для произвольной точки**: обобщить существующий OSM-landcover (он считает биотопы
   для полигона места) на запрос `lat,lng` → биотоп(ы) тайла. Это ключевой примитив (б).
2. **Эндпоинт «характерные рядом»** для точки: `GET /quests/nearby?lat=&lng=[&biotope=]` →
   топ-5 (гибрид выше: iNat-частота ∩ биотоп ∩ корпус-приоритет, с фото, дедуп). Можно как
   эволюция `build_walk` (он уже половина пути: GPS→iNat→узнаваемые→мост в корпус).
3. (опц.) **регион-фильтр** для (б) без точного GPS (чипы «где ты?» → биотоп+регион).
4. (опц.) **мини-челлендж над базой**: обернуть «5 рядом» в значок, чтобы прогрессия работала
   **везде**, а не только в покрытых местах.

## Фазы
- **P0 (сейчас, клиент-онли):** вариант (а) через `/quests/walk` → карточка «Рядом с тобой» на
  Home + замена пустого состояния Квестов. Универсальная польза немедленно.
- **P1 (бэк):** GPS→биотоп точки (п.1) + `nearby` (п.2) → вариант (б), чинит «поле vs лес».
- **P2:** мини-челлендж/значок над «5 рядом» (прогрессия везде).
- **Параллельно:** места-квесты/биотопы-места — заморозить как приоритет, оставить как enrichment.

## Чего НЕ делаем
- Не показываем счётчики/дампы корпуса по биотопу (директория «1296 в лесу» — снять).
- Не выдаём «квестов рядом нет» как конечный экран — там должен быть живой «рядом».
- Не меряем прогресс охватом городов — меряем тем, получает ли пользу юзер в произвольной точке.
