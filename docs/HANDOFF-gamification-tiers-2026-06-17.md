# HANDOFF → backend: уровневые бейджи мест + очки (мягкая прогрессия)

**От:** мобильный агент «Что растёт». **Дата:** 2026-06-17.
Контекст и решения: `PLAN-quests-progression.md`. Это actionable-задача на бэкенд.

## Зачем (проблема текущей модели)
Сейчас бейдж места бинарный, порог = `target` (≈15 видов). **Для новичка 15 видов за первый
бейдж — стена, после которой приложение закрывают.** Нужна мягкая лестница: первый бейдж
за 1 короткую прогулку, дальше — выше.

## Слой 1 (личный уровень) — УЖЕ НА КЛИЕНТЕ, бэкенд НЕ нужен
Клиент считает «уровень натуралиста» по числу определённых видов локально из Истории
(1/5/15/40/100 → Новичок→Любитель→Знаток→Мастер→Легенда). Это on-ramp с первого скана.
Бэкенду тут делать нечего (разве что позже — серверный счётчик для лидерборда, не сейчас).

## Слой 2 (БЭКЕНД): уровневые бейджи места — низкий вход + ступени
Превратить бинарный бейдж места×сезона в **3 ступени** одного бейджа:
- **Новичок** места — нашёл **3** вида набора (первый бейдж за прогулку);
- **Любитель** — ~середина (предлагаю `round((3+target)/2)`, для набора 30 → ~9);
- **Мастер** — полный `target` (0.6·set, cap 15).
(Пороги клампить: `1 ≤ t1 < t2 < t3 ≤ set_size`; для мелких наборов ужимать.)

Контракт (расширить существующие роуты):
```jsonc
GET /quests/badge/progress?device_key&place_id&window&year →
{
  "badge_id": "place:window:year", "set_size": 30, "matched": 5,
  "tiers": [ {"tier":1,"name":"новичок","need":3,"points":5},
             {"tier":2,"name":"любитель","need":9,"points":15},
             {"tier":3,"name":"мастер","need":15,"points":30} ],
  "current_tier": 1,        // высшая достигнутая ступень (0 = ни одной)
  "claimable_tier": 1,      // ступень, доступная к выдаче сейчас (>current_tier и need<=matched), иначе null
  "next_need": 9            // сколько видов до следующей ступени (null на максимуме)
}
POST /quests/badge/claim?...   // выдаёт высшую доступную ступень; идемпотентно per (place,window,year,tier)
   → {..progress.., "issued": true, "tier": 1, "name":"новичок", "ordinal": 37, "points": 5}
GET /quests/badges?device_key →
   [ {"badge_id","place_id","window","year","tier","name","points","ordinal","issued_at"} ]  // все ступени
```
- `ordinal` — порядок per ступень (редкость: «новичок #37»). Окно по-прежнему годовой инстанс.
- Клиент покажет **ближайшую** ступень («До „Новичка Битцы" — ещё 2 вида»), сезон — цветом (не в названии; склонять OSM-имена не будем).

## Слой 3 (БЭКЕНД): очки = сумма по ступеням, лидерборд
- Очки бейджа = `points` ступени (предлагаю 5/15/30 ≈ числу освоенных видов).
- **Счёт места = очки ВЫСШЕЙ достигнутой ступени** (НЕ сумма 5+15+30 — иначе двойной счёт).
- Общий счёт устройства = сумма по всем место×сезон высших ступеней.
- `GET /quests/leaderboard` (уже есть, v1 = 10×бейджи) → переключить на эту сумму; `me.rank` по
  убыванию, авто-ник как сейчас. Клиент уже рисует рейтинг.

## Порядок
1. Слой 2 (tiers в progress/claim/badges) — главное, разблокирует мягкий вход.
2. Слой 3 (points по ступеням в leaderboard).
Чистый пересчёт наборов после Layer-1 merge — как и договаривались (дубль-шум видов).
